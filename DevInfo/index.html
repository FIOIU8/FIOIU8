摘自 DevInfo README

DevInfo 将标识符、设备、系统、区域、显示、存储、电池、网络和应用信息汇入同一条浏览路径。使用者可以先从总览判断设备当前是否处于正常状态，再深入单项追踪数据来源，而不是在多个系统设置页之间来回跳转。

Capabilities

四种使用场景

01

建立设备档案

读取设备标识、系统版本、区域设置、显示特征、已安装应用与存储概况，为排查或分享保留一份完整底稿。

02

观察实时变化

CPU/GPU 频率与负载、内存和存储占用、电池状态、屏幕亮度、Wi-Fi 信号与存储读速共同构成即时仪表板。

03

识别系统风险

安全补丁日期、锁屏密码、USB 调试等状态会被纳入查看范围；其中调试开启时，界面会明确给出提醒。

04

打包当前配置

可将当前设备信息导出为适配 Magisk 与 KernelSU 安装脚本的机型模拟模块 ZIP，让一次观察能够延续到测试环境。

Implementation Notes

面向持续刷新的实现

容错采集

DeviceInfoCollector 以 supplier 列表逐项工作，某条信息读取失败不会中断整页数据，适合面对不同厂商与系统版本的差异。

状态有序更新

StateFlow 与 collectAsState 驱动界面，电池观察器通过 callbackFlow 接入系统广播；快照对象集中替换，避免数据在界面上零散跳变。

长期运行控制

CPU 采样使用弱引用避免持有界面，重载过程用 Mutex 防止并发冲突；版本检查通过 GitHub Releases API 获取结果并保留 12 小时缓存。

Platform Fit

外观与语言

基于 Jetpack Compose 与 Material 3 构建，Android 12 及以上可接入 Material You 动态取色；应用提供跟随系统、浅色、深色三种模式，以及 8 组预设颜色、中英日语言和自定义 locale。

安装与权限

最低支持 Android 11。项目将所有 uses-feature 标记为非必需，避免因硬件缺失阻止安装；网络、蓝牙、NFC、相机与存储等能力只服务于对应的信息读取场景。

发布与测试

GitHub Actions 覆盖 main/test 的开发构建，也支持手动触发 debug 或 release 工作流。测试包可从 Artifacts 获取，正式版本以 Releases 页面为准。
